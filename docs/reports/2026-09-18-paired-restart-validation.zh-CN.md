# 配对恢复实施与验收记录

日期：2026-09-18。范围：node4、IBAMR 0.18、GCC 9.5、Open MPI 5、uv Python 3.12.13、
Smarties 原生 CPU VRACER。操作说明：[成套保存与续算](../../couplings/ibamr/PAIRED_RESTART.zh-CN.md)。

## 实现内容

- 成套保存完整 learner 状态、proxy Agent 和进行中的 CFD；不是仅保存网络权重。
- 在等待下一动作的边界保存。恢复后只执行原来已选出的待执行动作，不重复反馈。
- 一个 `resume --run` 自动选择最新完整批次，读取原配置并恢复所有环境。
- 默认 30 分钟请求保存，保留最近两套。新批次写完并同步后才发布、清理最旧批次。
- 每次恢复另开 session，保留中断分支日志，不向旧 CFD 输出追加回退时间。
- 原有 MPI 所有权不变；不接入 PyTorch、CUDA 或 pybind11。

## 其他直接相关的验证

- 原生 learner：完成轨迹与活动轨迹续接、累计计数、随机数及缓存高斯样本、
  下一次 Adam/目标网络更新保持一致；3-rank/8-thread 的预热、已训练及各自恢复场景退出均为 0。
- 存储：18 项定向测试通过，覆盖半写批次、缺少成员、空间/fsync 失败、保留两套、
  符号链接和文件锁。没有真实断电或物理介质故障试验。
- 管理器：配置白名单、累计预算命令、独立输出目录、CFD/proxy 配对序号、全部 rank
  文件、发布失败释放暂停以及强杀管理器后旧 MPI 存活检测，定向测试通过。
- CFD：最初发现原生 restart 遗漏结构动量历史，导致后续 Fx 相差约 0.004。
  案例侧从 force evaluator 保存的动量补回后，重启后两步的 32 个比较量最大差异
  为 1.776×10⁻¹⁵。随后完成完整动作区间的连续/恢复对比：16 rank、32 个比较量
  均通过，最大绝对差异为 6.612×10⁻¹⁴；时间、相位和指令频率精确一致，
  其余量使用绝对容差 10⁻⁸、相对容差 10⁻⁶，没有放宽原容差。
- 对同一完整动作区间已有的 1251 行 Fx 输出做离线积分，连续/恢复的非终态推力
  奖励分别约为 0.128371703495603 和 0.128371703495587，差异 1.603×10⁻¹⁴。
  这是文本输出精度下的核对，不代表二进制逐位一致，也未额外运行 CFD。
- 保存/预算结束竞态：3-rank、8-thread 定向测试先完成周期保存后继续，令一个 proxy
  暂停、另一个跨过累计预算。修改前无法继续保存，测试限时退出 124；修改后完成最终
  保存和统一退出，退出 0。管理器相关 14 项测试通过，包括停止时不启动排队中的新回合。
  此修复位于完整 CFD 验收之后，采用原生 MPI 协议及管理器定向测试，没有重复物理长程运行。

## 结论范围

实际双 CFD 运行证明活动物理回合能够成套保存、正常退出、从原边界恢复并继续更新网络。
该次物理运行的保存点在预热期；已训练优化器状态的准确恢复由独立原生状态测试覆盖。
不承诺异步线程调度下未来曲线逐位重现、跨编译器/版本恢复或介质损坏恢复，
也不据此判断鱼游策略已收敛。
