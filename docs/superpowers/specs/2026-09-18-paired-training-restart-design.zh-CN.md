# Smarties–IBAMR 配对恢复与统一启动入口

状态：实现及限定范围的配对恢复验收已完成，见[验收报告](../../reports/2026-09-18-paired-restart-validation.zh-CN.md)；仅限相同构建与受支持拓扑，不代表跨版本恢复兼容。

## 1. 目标与范围

支持正在训练的 learner 与所有 CFD 环境成套保存，从最近完整保存点一起恢复，
不重置训练计数、不重新随机初始化正在进行的鱼游回合、不重复施加动作或奖励。
用户只需指定运行目录，无须手工配对网络权重、CFD dump 目录或恢复步号。

首期针对现有 node4 单机近壁 eel2d：一个 learner、两个 proxy、两个独立的
16-rank CFD 作业，learner 8 线程，原生 CPU 网络。首次部署提供 node4 路径配置。
恢复要求环境数、每环境 rank 数、算法、状态动作维数及兼容的代码/依赖版本不变。
不接入 PyTorch，不重构 MPI 所有权，不增加 hash、冻结 contract 或新 baseline。
实现校验保存的运行配置及原生文件格式；用户须保留相同构建及 IBAMR/MPI 依赖。
不自动检测 Git 版本或依赖的语义兼容性，即使路径不变也不能据此认定兼容；数据完整性使用普通校验与测试。

## 2. 方案选择

- **采用：动作安全边界的全局成套快照。** 包括中途 CFD 与中途训练轨迹。
- 不采用“只存 Agent，恢复时重开鱼游”：这不是用户要求的中途配对恢复。
- 不采用“等所有物理回合结束再存”：慢环境会延长保存延迟，且无法恢复中途鱼游。

继续使用非 MPI 管理程序协调独立 MPI 作业。管理程序不读写库的内存，
CFD 自行执行原生 restart I/O，learner 自行保存训练状态。

## 3. 统一命令

入口：`couplings/ibamr/scripts/run_near_wall.sh`。

```bash
# 新建训练：机器环境只需通过一个配置文件指定。
bash couplings/ibamr/scripts/run_near_wall.sh start \
  --run /absolute/path/run01 --config /absolute/path/node4.conf

# 从该运行目录最新完整保存点恢复；不需要其他必填参数。
bash couplings/ibamr/scripts/run_near_wall.sh resume --run /absolute/path/run01

# 请求成套保存并正常退出。
bash couplings/ibamr/scripts/run_near_wall.sh stop --run /absolute/path/run01
```

默认每 30 分钟墙钟时间请求一次保存，全局保留最近两套完整快照。
可选参数仅保留必要项：新建时的 `--checkpoint-minutes`、`--keep-checkpoints`，
恢复时的 `--checkpoint previous` 用于显式选择上一套。保留数至少为 2。
训练参数、MPI 配置、输入文件路径仍集中在配置中，CLI 不重复要求用户输入。
配置只保存运行所需的非敏感设置，不保存 SSH 密码、token 或整个 shell 环境。

`start` 拒绝复用已有运行目录；`resume` 要求存在完整配对快照。
用本机操作系统文件锁阻止同目录的重复管理程序；不凭过期 PID 杀进程。
`resume` 自动读取原运行配置，重新加载编译器/IBAMR/MPI 和 uv Python 环境，
校验文件与兼容性后启动 learner 和 CFD，全部就绪才释放暂停点。
恢复沿用原训练总预算，不把剩余任务误变为又训练同样多的步数。
已达到预算的任务明确报告完成，不自动开新训练。
配对模式达到预算时，learner 通知管理器并保持通信服务；管理器通过同一套成套保存、
释放停止和正常退出流程收尾，避免 learner 自行结束与 proxy 保存暂停发生死锁。
这可能需要等待正在执行的动作区间结束，并写入最后一套快照；非配对模式的退出行为不变。

前台 `Ctrl+C` 与 `stop` 请求相同：保存后退出。后台运行时可用 `stop`，
用户不需要手动向各 MPI rank 发信号。原有 node3 入口保留兼容。

## 4. 保存边界和协调顺序

1. 管理程序收到周期保存或停止请求，暂停启动新的物理回合。
2. 各环境完成已经收到的动作区间，提交一次反馈；proxy 在发出下一动作前停住。
   请求期间已在途的动作允许完成，不丢弃或重复；每环境明确报告最终动作序号。
3. learner 消化截至这些边界的反馈，停止发新动作，在完整网络更新之间暂停。
   清空或保存关联队列，确保代理、轨迹缓存和 learner 对样本的接收边界一致。
4. CFD、learner、proxy 和管理程序将配对数据写入同一临时批次目录。
5. 所有参与方写完、关闭文件并报告成功后，执行持久化与目录发布。
6. 成功后更新最新恢复点、按规则清理最旧完整批次，再继续计算；停止请求则正常退出。

不同环境的物理时间和回合号可以不同；配对的是同一全局暂停边界，而非相同时间值。
一个环境已经终态时记录“下一回合尚未启动”，不得恢复到该终态后继续施加动作。
保存周期从上一套成功发布后重新计时；未完成的请求合并，不排队堆积。
物理推进慢不作为失败或超时依据；输出等待哪个环境、哪个动作区间的信息。

## 5. 必须保存的状态

| 归属 | 状态 |
|---|---|
| learner | 策略及目标网络、优化器、归一化、replay、更新/采样/预热计数、算法运行状态、相关随机数发生器 |
| proxy/Agent | 正在进行的轨迹、上一观测/动作及算法所需的行为策略信息、样本归属与消息序号；不能仅保存已结束轨迹 |
| CFD | 原生 IBAMR/SAMRAI restart；通过读取恢复数据库重建当前时间、网格、流场、结构及库级状态 |
| 案例侧 | 尾摆相位及频率、上一频率与限幅历史、回合初始位置/进度参考、控制计数、观测所需历史和终止状态 |
| 管理程序 | 回合编号、下一回合种子生成状态、环境对应关系、暂停边界、累计预算与相关运行配置 |

原生 CFD restart 未覆盖的控制状态由案例侧明确序列化。受力计算等有历史的对象，
逐项核对原生 restart 覆盖范围，恢复后的首个动作和奖励也必须验证。
安全边界不存在半个动作区间，因此不需要恢复半区间积分；不得通过虚构终态来清空轨迹。
随机数状态保存不意味着异步线程和 MPI 调度可以逐位复现，首期承诺状态一致的续算。

## 6. 磁盘组织与断电安全

```text
run01/
  run-config.json
  checkpoints/
    snapshot-000001/    # 全套 learner、环境 restart、控制状态和对应信息
    snapshot-000002/
    .writing-000003/    # 尚未发布，不能用于恢复
  sessions/
    session-000001/    # 初次运行的通信、日志和输出
    session-000002/    # 恢复运行的独立通信、日志和输出
```

仅使用一个轻量的版本化对应文件描述批次及成员，不引入独立数据库或哈希链。
故障场景是“网络文件已写完，但一个环境写到一半时断电”；Git、文件版本号和类型
不能让多个运行期文件同时落盘。采用同一文件系统内临时目录、文件/目录同步和
原子发布形成普通文件事务；读取者只接受发布完成且成员齐全的目录。
掉电持久性仍受实际文件系统及存储硬件保证限制；不承诺损坏介质可恢复。

默认只保留全局两套，而非每个 episode 两套。新批次成功前不删除原两套；
写入期间峰值约三套，单套实际大小随 CFD 网格和 replay 大小变化。
首次测量并报告单套大小；后续结合实际大小与预留空间检查磁盘。
空间检查不能消除并发写满风险，任一写入失败不得发布新批次，保留旧快照并报告。
正常周期保存失败可继续计算并明确标记无新恢复点；用户请求保存后停止时不得假报保存成功。
发生不可恢复的分布式错误仍按既有 MPI 失败流程退出。

清理仅限此运行目录管理的旧快照及失败临时批次；校验解析后的目标路径，
不越过符号链接，不删除用户手工文件、普通输入、Agent 归档或可视化。
两套保留数只控制 checkpoint，CSV、日志和可视化仍按独立保留策略管理。

配对模式下统一调度原生 restart 写入，不让每步循环另行生成无人管理的周期 dump。
`restart_dump_interval` 不再充当网络的同步计数；其原有含义在非配对模式保留。

恢复必须另开 session 输出目录，保留中断之后的旧日志用于调查，
统计时不把旧分支与恢复分支重复相加，也不向旧 VisIt 时间序列追加回退时间。
最新完整批次不可读时明确报告，可用 `--checkpoint previous` 回退；不静默重开初始鱼游。

## 7. 代码边界

- 统一启动器、运行配置与 `external_episode_manager.py`：请求、配对发布、保留、恢复编排。
- `EpisodeMailbox.h`、`EelExternalAdapter.cpp`：暂停/恢复握手、序号、就绪状态。
- `EelNearWallAdapter.cpp`、`EelEnvironment.*`：安全边界、原生 restart 读写、案例历史恢复。
- `IBEELKinematics.*`、`TailBeatPhase.*` 和控制对象：控制状态序列化。
- Smarties Worker/Learner/MemoryBuffer/Agent 的实际状态所有者：更新间保存、活动轨迹与随机数状态恢复。

保留已经通过的 regrid 兼容修复，不在本功能中改变物理、奖励或训练算法。

## 8. 验收

1. 普通测试覆盖完整/半写目录选择、保留两套、空间失败、重复启动及累计预算。
2. node4 使用实际双环境各 16 rank、learner 8 线程，非初始频率下存一次配对快照。
3. 保存后停止，再用唯一的 `resume --run` 命令恢复；恢复时所有保存状态一致，
   首个动作、时间、频率/相位、奖励与相应轨迹计数不丢失、不重复、不重新随机初始化。
4. 用受控动作对比连续 CFD 与保存/恢复 CFD，使用明确数值容差，不要求浮点逐位一致。
5. 在新批次写入未完成时中断，确认旧完整批次仍可恢复；验证自动保留不会删掉唯一可用批次。
6. 恢复后继续发生有限值网络更新，预算结束正常退出且无残留 MPI 进程。

只做直接覆盖恢复语义与故障窗口的验证，不重复此前无关测试，不把编译通过当作恢复通过。
断电只能恢复至最近成功保存点；当前旧长程任务没有 CFD restart，不能补出其中途状态。
